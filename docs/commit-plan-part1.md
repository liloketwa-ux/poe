Use these as a guide and make each commit after actually completing the corresponding work in your own repository. The lecturer requires commits from your own GitHub account, so do not copy a pre-made Git history.

2. `docs: define RaceDay functional requirements and assumptions`

7. `docs: add Enrolments entity and participant relationship`
8. `docs: add Results entity and enrolment relationship`
9. `docs: add Routes entity and route relationship`
10. `docs: finalise ERD cardinality and keys`
11. `docs: create authentication endpoint plan`
12. `docs: create profile endpoint plan`
13. `docs: create event and category endpoint plan`
14. `docs: create enrolment endpoint plan`
15. `docs: create results endpoint plan`
16. `docs: add route and weather endpoint plan`
17. `db: create Users and Events tables`
18. `db: add Routes, Categories and Enrolments tables`
19. `db: add Results table, constraints and seed data`
20. `ci: add documentation validation workflow and update README`

After each commit, push to GitHub. Avoid empty commits and meaningless messages such as `updated file`.
